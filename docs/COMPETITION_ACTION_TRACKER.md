## C. 内部 benchmark 最低结构

```text
benchmark/cases/ey-campus-demo-v0.1/
├─ README.md
├─ case-01-noisy-transcript/
│  ├─ input/
│  ├─ gold/
│  └─ expected.md
├─ case-02-existing-note-growth/
│  ├─ input/
│  ├─ gold/
│  └─ expected.md
└─ case-03-repeat-example-and-link/
   ├─ input/
   ├─ gold/
   └─ expected.md
```

Gold 必须由参赛者确认。Agent 可以整理标注格式和计算覆盖率，但不能自行决定“正确笔记应该写什么”。

## D. 终端演示顺序

1. 选中赛事模拟输入和已有页面。
2. 指定 Human 和 AI 输出位置。
3. 运行第一次编译。
4. 展示正式 Human Note、AI index/cards、来源和验证。
5. 再提交一段补充材料。
6. 展示同一知识对象被扩展、原页面保留、双链增加。
7. 展示一项缺失证据被 deferred。
8. 展示 diff、回退边界和“生产 Vault 未写入”。

可直接执行的两次演示步骤见：[比赛演示 Runbook](COMPETITION_DEMO_RUNBOOK.md)。
每次运行的输入 hash、版本、耗时、验证结果、覆盖率和人工门记录见：[指标记录模板](COMPETITION_METRICS_TEMPLATE.md)。
