# 安永 CSDC Campus AI Innovation Challenge 参赛计划

> 依据：用户提供的《安永校园AI创新挑战赛.pdf》。
> 版本：Competition Plan v0.1。
> 适用项目：Learning Agent / learning-knowledge-growth。
> 目标：把当前可运行的 Codex Skill 收敛成一个可展示、可复现、符合赛事纪律的数据安全型 AI 效率工具。

## 1. 先确定参赛方向

这份 PDF 规定了两条赛道：

| 赛道 | 题目 | 与 Learning Agent 的匹配度 | 建议 |
| --- | --- | --- | --- |
| 个人赛 | AI 效率工具创作赛：用 AI 解决真实的学习/生活痛点 | 高。PDF 明确推荐文件智能管理、学习资料整理、论文辅助、信息检索与汇总、代码辅助等方向 | **首选** |
| 团体赛 | AI + Business Scenario：围绕安永提供的真实业务场景设计 AI 解决方案或 Demo | 中。现有产品可以复用知识编译和证据追踪能力，但必须改成指定审计业务场景 | 只有拿到题包并组队后再走 |

当前产品的参赛叙事应是：

> Learning Agent 是一个把转写、课件、文档和已有笔记整理成可复习、可连接、可持续更新知识库的 AI 效率工具。它保留已有有效知识，依据新材料扩展同一知识网络，并同时生成给人阅读的正式笔记和给 AI 检索的轻量索引。

不要把它包装成“自动摘要器”“全自动替人学习”或“已经是 Obsidian 插件”。这些说法超出当前可验证能力。

## 3. 产品问题与解决方案

### 3.1 用户问题

目标用户是拥有持续课程、自学和项目资料的大学生或职业学习者。典型问题不是“没有摘要”，而是：

1. 转写和课件是口语、跳跃、重复和不完整的，难以直接复习。
2. 每次使用 AI 都得到一篇孤立的新摘要，旧笔记中的有效内容无法继续生长。
3. 公式、例子、边界、方法和已有页面链接容易在压缩过程中丢失。
4. 人类笔记需要清晰可读，AI 后续检索又需要紧凑结构，两者混在一起会互相污染。
5. 用户不容易知道某个新结论来自哪段材料，也不容易回退一次错误更新。

### 3.2 解决方式

Learning Agent 每次接收一组材料和两个输出位置：

- Human layer：面向人复习的正式 Markdown 笔记；
- AI layer：面向后续检索和增量更新的 `index.json`、知识卡片、来源和关系记录。

运行时遵循：

```text
新资料
  ↓
bounded source reading
  ↓
source-grounded knowledge compilation
  ↓
匹配已有知识对象
  ↓
扩展页面 / 新建页面 / 添加双链 / 标记缺口
  ↓
验证与可回退报告
```

产品价值来自“知识持续生长”，而不是一次生成更多文字：

- 有效旧内容不因新资料未重复提及而消失；
- 新内容只有在来源或已有有效笔记支持时才进入正式笔记；
- 相关已有页面优先使用 Obsidian 双链；
- AI 索引只保存检索所需的稳定对象、关系和来源，不复制整篇人类笔记；
- 公式、链接、来源和不确定性在交付前经过检查；
- 失败时保留诊断目录，生产笔记不被静默覆盖。

## 4. 比赛 MVP

第一版参赛产品只承诺以下闭环：

1. 用户提交一份脱敏的 TXT/Markdown/PDF/PPT 或粘贴文本。
2. 用户指定 Human 输出目录和 AI 输出目录。
3. 系统识别主题，并读取少量已选的旧笔记。
4. 生成一页正式学习笔记，含定义、机制、公式、例子、边界、方法、比较或易错点中实际需要的部分。
5. 生成对应的 AI 索引和知识卡片。
6. 第二次提交同主题材料时，命中已有对象，扩展原页面并增加有依据的双链，而不是默认再建一篇孤立摘要。
7. 输出来源、变化、未解决证据和验证结果。
8. 用户审阅后决定是否写入个人知识库；系统支持回退到运行前状态。

当前已能展示的能力和参赛前必须补齐的证据要分开：

| 能力 | 当前状态 | 参赛前证据 |
| --- | --- | --- |
| Codex Skill 入口 | 已有 | 干净环境安装演示 |
| Human/AI 双层输出 | 已有 | 一次公开脱敏运行包 |
| 来源约束、公式、双链检查 | 已有 | 校验报告和失败样例 |
| L0 index + L1 cards | 已有 | 旧页、对象、关系、来源的截图/JSON |
| 增量扩展 | 已有设计和个人运行证据 | 两次输入更新同一对象的公开 fixture |
| 生产 Vault 安全边界 | 已有规则 | dry-run、diff、回退演示 |
| 独立可执行产品 | 尚未完成 | 需决定是否做本地 CLI/桌面包装；不能把 Codex 对话本身说成独立应用 |
| 公开 benchmark | 尚未完成 | 3 个脱敏案例和人工 Gold |
| 赛事可提交包 | 尚未完成 | 按第 8 节清单打包 |

## 5. 演示故事

演示使用一个合成或完全脱敏的“概率论/金融学/Java”小型课程，不使用个人 Vault 原文。

### 5.1 第一次输入

展示：

- 一段有重复、口语和公式的课程转写；
- 一页已经存在的旧知识笔记；
- 课程目录中若干可解析的已有页面；
- 用户指定的 Human 和 AI 输出目录。

演示结果：

- Human Note 中保留旧定义并补齐新材料支持的机制、公式、例子和边界；
- 可解析的已有主题变为 `[[双链]]`；
- AI index 指出相关页面和知识对象；
- 卡片带有来源、section anchor、关系和维护状态；
- 缺失的板书或无法辨认的公式被列为待补，而不是模型自行补写。

### 5.2 第二次输入

再提交一段同主题补充材料，内容只增加一个机制或例子。

展示：

- 命中同一个稳定知识对象；
- 更新同一页的对应小节；
- 增加一个有来源依据的链接；
- 未重复生成旧页面；
- AI 卡片 hash、来源和关系发生可解释变化；
- 输出更新前后 diff 和回退位置。

### 5.3 最后 30 秒

展示验证报告：

- 所有新增知识块都有来源或既有有效笔记引用；
- 有效旧内容未被静默删除；
- 公式定界符成对；
- 双链目标在 bounded snapshot 中可解析；
- deferred 项明确列出；
- Production Vault 未被直接修改；
- 用户可以选择接受或回退。

## 6. 评审对应关系

PDF 对个人赛没有给出量化评分表，因此以下是围绕 PDF 主题和奖项方向建立的内部验收表，不宣称是官方权重。

| 评审关注 | 我们要展示的证据 | 内部目标 |
| --- | --- | --- |
| 真实痛点 | 旧笔记、转写、新旧两次运行的 before/after | 评委能在 30 秒内理解问题 |
| 创意 | Human/AI 双层、可生长对象、来源约束、双链 | 不做普通一次性摘要 |
| 落地实践 | Skill 安装、输入说明、输出目录、失败回退 | 新用户可按 README 完成一次运行 |
| 学习效率 | 复习页更清晰、重复页减少、来源可追溯 | 用公开样例和人工标注证明 |
| 可信与安全 | 不使用真实敏感数据、证据不足时 deferred、人工写入门 | 0 个隐式事实扩写 |
| 可复现 | 固定 Skill 版本、输入 hash、run manifest、校验结果 | 同一 fixture 可重复运行 |

### 6.1 建议测量指标

所有数字先从 benchmark 测量后再写进答辩材料：

- `source_coverage`：人工标注的定义、机制、公式、例子、边界、方法中被正确保留的比例。
- `provenance_coverage`：新增知识块带来源或既有有效笔记引用的比例，目标 100%。
- `valid_content_preservation`：旧笔记中人工标注有效内容的保留比例，目标 100%。
- `wikilink_resolution`：输出双链在限定快照中的可解析比例，目标 100%。
- `unsupported_claim_rate`：无法追溯到材料的新增断言比例，目标 0%。
- `incremental_match_rate`：第二次输入更新已有对象而不是重复新建页面的比例。
- `run_reproducibility`：相同 fixture 的结构、验证结果和页面命中是否稳定。
- `runtime_and_tokens`：与“整库读取、每次重新摘要”的基线比较。
- `human_review_time`：用户从结果到可接受版本的审阅时间。
- `rollback_success`：候选写入失败后是否能恢复运行前状态。

不得在没有结果之前声称“节省了多少 Token”“准确率提高多少”或“完全自动化”。

## 7. 数据、原创和知识产权方案

PDF 要求：

- 作品原创，禁止抄袭、盗用和代做；
- 仅使用赛事提供的模拟数据；
- 禁止使用、传播企业或客户真实敏感数据；
- 学生原创作品著作权归参赛选手；
- 安永在取得书面同意后拥有非商用展示、案例收录使用权。

因此参赛仓库和演示包采用三层数据策略：

1. **公开仓库**：只放代码、Skill、提示规则、schema、测试、合成材料和脱敏截图。
2. **演示包**：只放人工确认可公开的合成转写、合成旧笔记、运行清单和结果。
3. **个人工作区**：真实课程材料和个人 Vault 只留在本地，不纳入 Git、不进入提交包。

所有演示数据的 `provenance` 仍要写明来源类型：`synthetic_fixture`、`deidentified_fixture` 或 `competition_simulated_data`。不要把合成数据伪装成真实课堂记录。

## 9. 工作分解与负责人

### 阶段 A：比赛和数据边界确认

**Agent 可完成：**整理 PDF 条款、生成检查表、扫描仓库是否包含密钥或个人材料。  
**必须人工完成：**确认赛道、资格、队伍、是否允许 Codex 作为开发辅助、是否允许展示脱敏材料、是否同意非商用展示和案例收录。

完成条件：所有第 2 节复选框有答案。

### 阶段 B：冻结可参赛版本

**Agent 可完成：**清理公开文档边界、生成版本号、运行 `npm run check`、`npm test`、`npm run typecheck`、生成 Skill ZIP 和 hash。  
**必须人工完成：**决定公开许可证、决定是否把当前 `codex/knowledge-compilation` 合并/标记为 release、确认不包含真实课程资料。

完成条件：干净 clone 能安装 Skill，所有检查通过，无密钥和个人文件。

### 阶段 C：建立 benchmark 和 Gold

**Agent 可完成：**建立目录、复制合成输入、运行 pipeline、汇总差异和统计。  
**必须人工完成：**为每个案例标注必须保留的知识单元、允许合并的重复、公式和边界是否正确。Agent 不得自行制造 Gold。

完成条件：3 个案例均有输入、Gold、输出、验证和回退记录。

### 阶段 D：做一次端到端演示

**Agent 可完成：**按固定脚本运行两次输入，生成报告、截图清单和演示数据。  
**必须人工完成：**选择最终故事、确认人类可读效果、决定是否接受候选更新。

完成条件：5 分钟内能从输入走到 Human/AI 双层输出和可回退报告。

### 阶段 E：答辩材料

**Agent 可完成：**生成讲稿初稿、架构图、指标表、风险表、Q&A 题库。  
**必须人工完成：**核对个人经历和贡献、录制视频/现场演示、确认所有数字和表述真实。

完成条件：任何一句“提高/节省/准确”都能定位到 benchmark 报告。

### 阶段 F：正式提交

**Agent 可完成：**整理文件命名、检查链接、打包、生成提交前清单。  
**必须人工完成：**填写报名、上传材料、确认授权、提交作品。提交后保留最终 hash 和截图。

## 11. 当前仓库的具体准备任务

按优先级执行：

### P0：比赛安全和可提交性

1. 选择个人赛作为默认路径，除非拿到业务题包并组队。
2. 建立 `benchmark/cases/competition-demo/`，只放合成或已获授权材料。
3. 为每个案例建立人工 Gold 和覆盖清单。
4. 生成一份端到端 demo runbook，不能依赖旧 DSH/低模型手册。
5. 确认公开许可证；当前 `package.json` 仍为私有项目设置，不能直接视为已开源。
6. 决定公开分支或 release tag；评委不应被要求猜测使用哪个分支。

### P1：证据和演示质量

1. 给每个公开案例记录输入 hash、Skill 版本、模型环境、运行时长、调用数、验证状态。
2. 展示 Human Note 和 AI index/cards 的对应关系。
3. 展示一次扩展已有页面和一次 deferred。
4. 用同一 fixture 做第二次复演，保存结构化 diff。
5. 生成简短的“为什么不是普通摘要器”对比页。

### P2：产品包装

1. 将 README 的 Codex Skill 入口作为唯一正式入口。
2. 将旧 DSH/低成本模型文档标成历史实验或移入 archive，不放进比赛操作路径。
3. 提供 Skill ZIP、安装检查和卸载/回退说明。
4. 明确当前不承诺后台监听、独立桌面应用、自动写入生产 Vault。
5. 确认个人赛作品是否需要独立运行包装；若赛事不允许依赖外部商业成品，优先补一个本地可复现包装，并在答辩中如实说明 Codex 的开发辅助角色。

## 12. 风险表

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 报错赛道或资格不符 | 直接失去参赛资格 | 以 PDF 和赛事联系人确认结果为准 |

| 生成笔记看起来漂亮但没有证据 | 可信度下降 | 来源引用、deferred、Gold 和回归测试 |
| 演示只能在个人电脑运行 | 评委无法复现 | 准备干净环境和固定 fixture |
| 把个人 Vault 放进仓库 | 隐私/版权泄露 | 路径扫描、secret scan、人工发布门 |
| 只展示一次成功运行 | 无法证明“生长” | 必须展示第二次资料扩展同一对象 |
| 指标未经测量 | 答辩失信 | 只报告可复现的实测值 |
| README 和旧运行文档冲突 | 评委误用 | 公开路径只保留 Codex Skill 入口，旧文档标历史 |

## 13. 完成定义

只有以下条件全部满足，才把项目称为“可提交”：

- 赛道、资格、队伍、授权和数据边界已由参赛者确认；
- 公开仓库不含真实课程笔记、敏感数据、API Key 或未授权素材；
- 一个干净环境能安装指定版本 Skill；
- 至少 3 个脱敏案例有人工 Gold、输入、输出和验证报告；
- 至少一次演示展示“已有笔记 + 新材料 → 同页增量生长”；
- Human layer 与 AI layer 可相互定位；
- 公式、双链、来源、旧内容保留和 deferred 均有可检查证据；
- 所有性能或质量数字都有运行记录；
- 版本、hash、贡献说明和许可证明确；
- 演示材料、技术说明、风险说明和报名信息经人工最终确认。
