# 比赛演示 Runbook：两次增量知识生长

> 版本：Competition Demo Runbook v0.1
> 依据：用户提供的《安永校园AI创新挑战赛.pdf》与仓库当前 `learning-knowledge-growth` Skill。
> 资料边界：正式演示只使用赛事提供的模拟数据。个人生产 Vault、真实课堂录音、企业数据或客户数据不默认进入演示；任何例外都必须先取得主办方书面确认。

这份 Runbook 只描述一次可以复演的产品演示。它不把内部中间产物当成产品功能，也不把尚未测量的效果写成比赛结论。

## 演示目标

在 3--5 分钟的现场流程中，让评委看到同一个学习主题经过两次输入后持续生长：

1. 第一次输入把一份学习材料和一份已有知识页整理成正式 Human Note，并生成对应的 AI 检索层。
2. 第二次输入只增加一个新材料片段，系统命中已有主题，扩展原页面或增加有依据的连接，而不是默认生成一篇孤立摘要。
3. 每次结果都能回到来源、已有内容、验证报告和可回退边界。

“3--5 分钟”是本 Runbook 的演示目标，不是 PDF 规定的时限；如赛事后续通知另有要求，以通知为准。

## 固定演示边界

| 项目 | 演示约束 |
| --- | --- |
| 参赛路径 | 默认按个人赛“AI 效率工具创作赛”准备；若改参加团体赛，必须替换为安永提供的业务场景包。 |
| 输入 | 仅使用赛事提供的模拟数据；其它数据类型保持 UNKNOWN，直到取得主办方书面确认。 |
| 输出 | Human Note（给人复习）与 AI index/cards（给后续检索和增量更新）。 |
| 运行入口 | Codex 中调用 `$learning-knowledge-growth`。 |
| 工作目录 | 使用独立的演示沙盒，不直接写 Production Vault。 |
| 原始资料 | 保持只读；记录文件名、类型、SHA-256 和来源说明。 |
| 公开材料 | 只在人工审阅通过后复制到公开仓库或提交包。 |

## 演示目录约定

演示材料准备在仓库可追踪、但不包含个人资料的目录中。Agent 可以创建目录和报告，但不能自行伪造 Gold：

```text
benchmark/cases/competition-demo/
├─ README.md
├─ case-01-first-growth/
│  ├─ input/                 # 赛事模拟材料
│  ├─ seed-human/            # 已确认可公开的初始知识页
│  └─ gold/                  # 由参赛者人工确认
├─ case-02-incremental-growth/
│  ├─ input/                 # 同主题的补充材料
│  └─ gold/                  # 由参赛者人工确认
└─ expected/                 # 覆盖、链接、保留内容的人工清单

benchmark/results/competition-demo/
├─ run-01-first-growth/
│  ├─ manifest.json
│  ├─ validation.json
│  ├─ human-note.md
│  ├─ ai-index.json
│  └─ review.md
└─ run-02-incremental-growth/
   ├─ manifest.json
   ├─ validation.json
   ├─ human-note-diff.md
   ├─ ai-index-diff.json
   └─ review.md
```

`benchmark/results/` 中只能放人工确认后的脱敏结果；本地临时运行目录可以位于 Skill 配置的 AI 输出根或独立工作区，但不要把临时目录作为公开证据。

## 演示前准备

### A. 选择赛道与数据

人工确认并勾选：

- [ ] 选择个人赛或团体赛，且不同时参加两条赛道。
- [ ] 若参加个人赛，确认案例属于学习/生活痛点；若参加团体赛，已取得安永业务场景包。
- [ ] 确认演示输入只含赛事模拟数据；若含其它材料，已取得主办方书面确认并留存证据。
- [ ] 删除文件名、路径、截图和正文中的姓名、学校、企业、客户及其它不必要个人信息。
- [ ] 确认作品由报名主体独立完成，未使用代做、外购成品或直接套用他人成果。

PDF 明确规定的赛道、原创和数据安全要求由参赛者最终确认；Agent 不能代替参赛者作资格或授权判断。

### B. 固定版本与输入

Agent 执行：

1. 记录 Git commit、Skill 文件 hash、运行时间和当前 Codex 环境。
2. 为每个输入计算 SHA-256，并保存来源类型（例如 `competition_simulated_data`）。
3. 检查 Human 输出根和 AI 输出根都是演示沙盒路径。
4. 检查已有种子页和第二次补充材料的主题相同、范围明确。
5. 清空或隔离旧运行输出，避免把上次结果误当本次结果。

人工确认：

- [ ] 第一次材料确实足以形成一个完整、可复习的主题页。
- [ ] 第二次材料只补充或修正同一主题的一部分，能观察到增量变化。
- [ ] Gold 清单列出必须保留的定义、机制、公式、例子、边界、方法、比较或易错点；没有证据的项目标为“不适用/待补”，不由 Agent 猜测。

## 第一次演示：首次编译

### 输入

在 Codex 对话中：

```text
$learning-knowledge-growth
请使用演示沙盒中的赛事模拟材料，整理主题：<主题名>。
人类笔记目录：<case-01 的 Human 输出目录>
AI 知识目录：<case-01 的 AI 输出目录>
已有种子笔记：<case-01 的 seed-human 路径>
只使用提供材料和已有有效笔记；不得补写材料没有支持的事实。
生成正式 Human Note 和对应 AI 检索层，保留来源、公式、边界与可解析双链。
```

### 运行后检查

Agent 记录：

- 输入文件和 SHA-256；
- 输出目录、run ID、Skill 版本和模型环境；
- Human Note 路径；
- `index.json` 与 `cards/` 路径；
- 验证状态、deferred 项、缺失证据、增加或更新的链接；
- 是否写入 Production Vault（应为否）。

人工检查：

- [ ] Human Note 是直接的知识表达，不是“课堂上老师说了什么”的流水账。
- [ ] 已有有效内容仍在；新增内容都能回到输入材料或已有有效笔记。
- [ ] 公式定界符、代码块、表格和 Obsidian 双链可正常解析。
- [ ] 不确定内容被明确标记，没有被写成无条件客观事实。
- [ ] AI 层可以从课程索引定位到知识卡、Human Note 页面和来源。
- [ ] 结果可阅读，且没有 candidate/draft/preview 等流程词进入正式标题或正文。

人工在 `review.md` 记录：接受、退回修补或停止本次演示。没有人工接受，不把结果复制为公开证据。

## 第二次演示：同主题增量更新

### 输入

使用同一 AI 知识目录和同一 Human 输出目录，提交 `case-02` 的补充材料：

```text
$learning-knowledge-growth
沿用上一轮主题和 AI 知识目录。
这是同一主题的新补充材料，请优先扩展已有页面和知识对象。
保留已有有效内容，只吸收本次材料支持的新增内容；相关已有页面使用可解析 [[wikilink]]。
请输出更新后的 Human Note、AI index/cards、来源和变更报告。
```

### 必须展示的变化

- 命中同一知识对象或原页面，而不是无理由新建重复页；
- 新增的小节、公式、例子、边界或方法能定位到第二次材料；
- 原有有效内容没有因为第二次材料未重复提及而消失；
- 有依据的页面关系变成可解析的 `[[双链]]`；
- 证据不足的项目保持 deferred/待补状态；
- AI 层记录来源、关系、旧/新 hash 或变更摘要；
- `human-note-diff.md` 能说明发生了什么变化，并支持人工回退。

人工检查：

- [ ] 更新目标确实是同一主题，而不是误合并相邻概念。
- [ ] 变更范围符合第二次材料，没有整页无证据重写。
- [ ] 新旧内容的差异可读，未静默删除有效内容。
- [ ] 人工决定接受更新、退回修补或保持原页。

## 评委现场口述顺序

1. **痛点（20 秒）**：一次性摘要会产生孤立页面，学习者需要一个会持续生长、可追溯的知识库。
2. **第一次输入（60 秒）**：展示材料、种子页、正式 Human Note、AI 索引和验证结果。
3. **第二次输入（60 秒）**：提交补充材料，展示同页增量、双链和来源变化。
4. **可信边界（30 秒）**：展示公式检查、来源覆盖、deferred 和 Production Vault 未写入。
5. **价值（30 秒）**：说明它服务于学习资料整理这一真实学习痛点；不要使用尚未测量的节省 Token、准确率或效率数字。

若现场时间不同，保持“第一次结果 → 第二次增量 → 验证与边界”的顺序，不牺牲第二次增量证据。

## 失败与回退

| 情况 | 现场处理 |
| --- | --- |
| 输入或输出路径不清 | 停止演示，使用预先验证的沙盒路径；不扫描整个 Vault。 |
| 公式、链接或来源校验失败 | 展示失败报告，回到局部修补；不把失败产物称为完成结果。 |
| 证据不足或术语无法确认 | 保留 deferred/待补，并说明需要什么证据。 |
| 增量误命中页面 | 退回更新，展示原页面仍完整；必要时改为新页面。 |
| Codex 环境不可用 | 使用已审核的开发合成结果和 manifest，明确这是内部回放而非正式竞赛输入或现场生成。 |
| 公开材料含个人或敏感信息 | 不发布，回到人工数据门。 |

严禁为了现场效果直接改 Production Vault、删除旧知识或隐藏失败报告。

## 演示完成判定

只有以下证据都存在，Runbook 才能标记为 `PASS`：

- [ ] 两次运行使用同一主题和可追踪输入；
- [ ] 两次运行均有 manifest、输入 hash、验证状态和输出路径；
- [ ] 第一次运行生成 Human/AI 两层结果；
- [ ] 第二次运行证明了已有知识对象或页面的增量变化；
- [ ] Gold 由参赛者人工确认，覆盖率可计算；
- [ ] 公式、双链、来源、旧内容保留和 deferred 均有检查记录；
- [ ] 所有数据符合 PDF 的模拟数据与安全边界；
- [ ] 公开材料不含真实 Vault、个人信息、企业/客户敏感数据、密钥或未授权第三方内容；
- [ ] 参赛者完成人工门 H0--H6 中适用于本次提交的项目；
- [ ] 没有把内部中间文件、未验证数字或失败结果包装成正式功能。

**Run status：** `NOT_STARTED` / `IN_PROGRESS` / `PASS` / `BLOCKED_BY_HUMAN_GATE`
