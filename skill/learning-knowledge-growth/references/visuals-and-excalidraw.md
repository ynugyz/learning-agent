# 图形辅助与 Excalidraw

这是一条由来源内容和理解收益触发的 Human-layer 视觉通道，不是第五张机器表。流程、几何、函数、空间和数量关系都可配图；来源不必已有图片。目标是减少理解难度，同时保留可检索的文字和来源。

## 工具与自检循环（先读这里）

图的质量靠工具和“看一眼再交付”保证，不靠手摆坐标。Skill 自带四个脚本，都只读写本地文件、不联网：

| 脚本 | 做什么 |
| --- | --- |
| `scripts/excalidraw_figure.py` | 从一个小 JSON 描述生成 `.excalidraw.md`：坐标系、按公式计算的曲线、曲线移动、点和辅助线、刻度、多面板并排、带标签的方框和绑定箭头；标签自动避开线和文字 |
| `scripts/excalidraw_review_map.py` | 从卡片 `relations` 生成章节复习地图，箭头绕开方框，超过约 1400 像素自动换行 |
| `scripts/render_excalidraw_preview.py` | 把场景渲染成 SVG；本机有 Chromium 系浏览器时再出 PNG，用来亲眼检查 |
| `scripts/lint_excalidraw_layout.py` | 版式检查：字太小、文字被线穿过、文字互相重叠为 FAIL；方框塞满段落、图注写进图里、手绘风格、纯方框图为 WARN |

每张新图或改过的图都走一遍：

1. 写 JSON 描述（坐标用数学坐标，曲线写公式 `expr`），运行 `excalidraw_figure.py spec.json --out-dir <课程>/_assets/learning/diagrams --preview <run>/preview.svg`；
2. 用 `render_excalidraw_preview.py ... --png` 出图，**打开 PNG 看一遍**：曲线形状对不对、标签是否压线、面板是否对齐；
3. `lint_excalidraw_layout.py` 为 PASS，`validate_excalidraw.py` 为 PASS 才交付；WARN 要么修掉，要么在运行摘要里写明理由；
4. 预览图留在 run 工作区，不放进 Vault。

一个两面板供求图的描述示例（数值只是格式示例）：

```json
{"name": "外汇市场-需求右移",
 "elements": [
  {"kind": "plot", "x": 80, "y": 140, "w": 380, "h": 280, "xrange": [0, 1], "yrange": [0, 1],
   "xlabel": "Q", "ylabel": "汇率 q", "title": "人民币资产市场", "subtitle": "需求右移",
   "curves": [{"expr": "0.15 + 0.7*x", "from": 0.1, "to": 0.95, "color": "ink", "label": "S"},
              {"expr": "0.9 - 0.7*x", "from": 0.05, "to": 0.95, "color": "blue", "label": "D₁"},
              {"expr": "1.05 - 0.7*x", "from": 0.25, "to": 1.0, "color": "red", "dashed": true, "label": "D₂"}],
   "segments": [{"from": [0.3, 0.72], "to": [0.45, 0.72], "color": "red", "arrow": true}],
   "points": [{"at": [0.5357, 0.525], "color": "blue", "label": "E₁", "guides": true}]}]}
```

**质量底线**（2026-11 一次实际运行的教训：外汇供求图被画成 7 个塞满文字的方框，标签压在箭头上，图注写进了图里，RNN 画成 5 个用无向线连着的方框）：

- 课上讲的是曲线移动、坐标或形状，就画坐标图；不要用“方框里写‘需求右移 → q↓’”代替曲线。
- 方框里只放名称和一行提示（不超过 4 行、约 60 字）；解释写在笔记正文。
- 时间展开、序列、网络结构这类图要画出结构本身（例如 RNN 按时间步展开、箭头有方向），不是把概念名排成一圈。
- 图中不写“示意图”“据课堂口述重绘”“来源”，这些写在嵌入下方的 Markdown 图注里。
- 不用手绘风格（`roughness` 为 0），字号按显示宽度保证约 12 像素以上（场景宽 1200 时至少 18–20）。

## 按理解问题选择表达

先问这张图要回答什么，再选工具；三种形式各管各的，不按“轻重”互相替代：

| 理解问题依赖什么 | 用什么 |
| --- | --- |
| 形状、位置、方向、曲线移动、坐标、几何、数据走势，或多个图形并排对比 | **Excalidraw**（数据图可加可交互 HTML，见下文） |
| 没有空间含义的流程、因果链、传导路径、层级 | **Mermaid** 代码块 |
| 属性对比、分类、“理论—假设—能解释—不足”对照 | **Markdown 表格** |

用文字或表格描述“向上倾斜”“需求曲线右移”不算完成视觉决策；需要看形状、看移动时就画。表格和图可以并存：图回答“长什么样”，表回答“谁有什么性质”。不要画内容与同页表格重复的方框加箭头关系图。

### 课堂图示复述

转写里能看出老师在画图或指着图讲（“纵坐标是价格”“需求曲线向右移动”“我们画三个坐标”“这条红色曲线”），而原图没有随资料提供时，按口述把这张图重画成示意图，放在对应小节旁边：

- 只画口述中能确定的坐标轴、曲线、移动方向、均衡点和标注；颜色、具体数值和看不清的部分不补。
- 图注写“据课堂口述重绘｜示意图，未按比例”。口述给了数值（例如几个期限的收益率读数）时，按数值描点，并写明只有这些点。
- 老师用同一套图分析多个情形时（例如违约风险和税收都用两市场供求图），画一张代表图，正文说明其他情形同理；确实有不同结论时再分开画。

### 多面板并排对比

两种以上情形需要比较时（国债与企业债、正常曲线与倒挂、长期与短期债券市场、四种曲线形状），在一张 Excalidraw 里横向排列多个小坐标系：坐标轴方向、标签和比例保持一致，每个面板只突出它和其他面板的差别。供求推导类的图按“冲击 → 各市场的需求或供给移动 → 价格和收益率 → 结论”从左到右排列。

### 可交互 HTML 图

数据走势、多条序列、需要悬停读数或切换显示时，可以在 Excalidraw 或静态 SVG 之外，再生成一个可交互的单文件 HTML 图：

- 单文件、自包含：数据内联，不加载外部脚本、字体或网络资源，不读写宿主存储。
- 放在 Human root 的 `_assets/learning/interactive/`，按用户已安装的嵌入插件写法嵌入：Embed HTML 用 `![[文件名.html|-]]`（`-` 表示高度适应内容）；HTML Prototype Viewer 用 `html-preview` 代码块。先看 Vault 的 `.obsidian/plugins/` 里有没有 `embed-html`（Embed HTML）或其他 HTML 嵌入插件；有就直接用对应写法，确实看不到插件时才只嵌静态图并在摘要里说明。
- 同一张图总是同时提供静态版本（`.svg` 或 Excalidraw）：装了插件时交互图放在正文，静态版本放进折叠块备用；没装插件时静态图放在正文。交互图只增加读数和切换，不承载静态图里没有的结论。
- 交互图跟随宿主的明暗主题，主题切换后要重绘，不能只在加载时读取一次。

### 可交互机制模型

核心机制由一个公式或一组变量关系驱动，而课堂讲的正是“某个量变了，结果怎么变”时（例如预期平均加溢价决定收益率曲线、需求移动决定价格和收益率、复利期数决定终值、杠杆放大每股收益、逐笔业务改变会计等式两边），**要**做成能拖动参数的单文件 HTML 模型。从 `assets/interactive-model-template.html` 复制，只改其中的 `MODEL` 块（参数、预设、曲线、数值表和结论句）：

- **只算资料给出的关系**：公式、变量和变化方向来自课堂或教材；模型计算必须可复算，交付前至少用一组参数手算核对。
- **演示假设要写明**：为了能动起来而补的设定（例如溢价随期限线性增加、示意数值）在页面上和对应卡片的 `uncertainty` 中各写一句，并提供回到课堂原始情形的设置（例如把溢价设为 0 即回到纯预期理论）。
- **预设对应课堂情形**：每个预设按钮对应资料中的一个情形或事实（正常曲线、倒挂、“预期小幅下降但曲线仍向上”等），按钮名用课堂说法。
- **显示结论而不只显示曲线**：同时给出数值表和一句由数值判断的结论（例如“曲线形状：向下倾斜”）。
- **放在讲解之后**：先用文字讲清机制，模型紧跟其后，图注一句话说明拖什么、看什么；静态备用图用几个预设并排的小图，放进折叠块。
- 定义类、只需记住的内容不做模型；每节最多一个，只给最核心、最难凭想象理解的机制。
- **每个核心机制都要有交代**：运行摘要逐条列出本次的核心机制，写出模型文件名，或写明为什么不做（例如“只是定义”“资料没有给出变量关系”）。“想保持轻量”不是理由。

## 章节复习地图

用 `scripts/excalidraw_review_map.py` 生成（说明见脚本开头）：它只读卡片的 `relations`，输出 `boxCrossings`、`labelOverlaps` 和 `smallText`，三项都为 0 才交付；不为 0 就调整节点顺序、`cols` 或 `rowBreaks` 再生成。

每个章节（同一 MOC 小节或同一组主题页覆盖的知识对象）维护一张 Excalidraw 复习地图，把 AI 层已有的关系画成可以点击的网络，供复习时从整体结构进入具体小节：

- **何时生成或更新**：该章节已有约 6 个以上有关系的知识对象时生成；之后每次运行改变了这一章的知识对象、关系或标题，就更新同一张地图。文件放在 Human root，命名为 `复习地图-<章节名>.excalidraw.md`，从章节主题页的“与其他主题的连接”一节链接过去。
- **节点**：每个 `growing` 或 `stable` 的知识卡片一个圆角方框，两行文字：术语 + 一句话要点（取自 `semanticCore`，约 12 字以内）。方框的 `link` 写 `[[家页面#小节]]`，指向卡片的第一个 `sectionRefs`。课次页、MOC、`deferred` 和待补对象不进地图；`knowledgeRole` 为例子（example）或边界（boundary）的卡片不单独成节点。本章以外但有关系的页面画成灰色虚线框。
- **区域**：每篇家页面一块浅色底的区域，标题即页面名并链接到该页；节点放在它的家页面区域里。
- **箭头**：只画卡片 `relations` 中已有的关系，不新增；互为反向的同一对关系合成一条（优先级：属于 > 应用于 > 对比 > 例证 > 相关）；同一家页面内已由页面结构表达的“相关”可以省略。箭头两端与方框双向绑定，箭头上标中文关系名：属于、应用于、对比、例证、相关，其他已有类型按含义译名（使用、前提、特例、推广、近似、细化、扩展、解释、简化）。同名不同义等易混关系在标签中写明，例如“对比：同名不同义”。
- **缺少关系时**：本章卡片之间没有记录关系，而课堂明确讲了它们的联系（例如"神经元构成多层感知机""Softmax 是交叉熵的前提"），先在本次 Alignment 中按 RELATION 补到卡片上、附来源位置，再画图；不为了画图编造关系。
- **排版**：箭头不得穿过其他方框和区域标题；需要跨区域时沿区域之间的空隙或画布边缘折线绕行。节点字号约 22，标签约 17，地图标题写明“Ctrl/Cmd + 悬停预览，点击打开对应小节”。
- **保留用户修改**：更新时先读取现有地图。用户移动过的节点保持位置；用户自己加的元素、批注和箭头原样保留；只新增缺少的节点和箭头（放在所属区域的空位），更新改名后的链接；已删除的知识对象对应的节点改为灰色并在标签中注明，不直接删掉用户可能还在用的元素。用户手画的新箭头只作为关系线索，在下一次 ChangePlan 中提出，不自动写入 AI 层。
- **检查**：运行场景校验（旧场景若是 compressed-json 格式，校验器读不了，如实报告而不是判为损坏）；逐个确认节点和区域的链接能解析到真实的笔记和标题；渲染一次预览，确认没有箭头穿过方框、没有标签互相遮挡。
- **AI 层**：在章节主题页的记录 `attachments` 中登记一次，`kind: "excalidraw-review-map"`，`generatedFrom: "ai-relations"`。地图是关系的视图，不是新的知识来源；地图与 AI 层不一致时以 AI 层和 Human Note 为准。

## 嵌入与排版

- **图单独成段**：`![[...]]` 独占一行，前后各留一个空行；绝不插进一句话或一个段落中间，否则 Obsidian 会把图和文字排在同一行。在 callout 里也一样，图单独占一行 `> ![[...]]`，前后用 `>` 空行隔开。
- **放在讲它的那段话之后**：先用文字讲清结论，紧接着放图，图下一行写图注。
- **图注写在 Markdown 里，不写进图里**：图中只保留坐标轴、曲线名、关键标注和面板标题；“据课堂口述重绘｜示意图，未按比例”、解释性句子和来源写成图下方的一行普通文字（或 `*斜体*`），方便阅读、检索和选中追问。
- **字号按显示宽度设计**：笔记正文宽度通常约 700–900 像素。按目标显示宽度缩放后，图中最小文字不小于约 12 像素（场景宽 1200 时字号至少约 20）。面板太多时减少面板或分成两张图，不要靠缩小字号塞进一张。
- **指定嵌入宽度**：Excalidraw 嵌入写宽度，例如 `![[文件名.excalidraw.md|900]]`，避免插件默认宽度把图缩得太小；宿主会按正文宽度自动收窄。
- **按文件名嵌入**：附件名保持唯一，嵌入时只写文件名，不写文件夹路径，这样笔记移动或 Vault 根目录不同时链接仍能解析。
- 数据来源和处理方式写在图注里；数据来自外部时同时遵循 note-writing.md 的“外部补充”规则。

## 先做视觉决策

对每个候选图形先选择一个 `visualNeed`：

- `none`：文字、公式或普通列表已经足够；不生成装饰图。
- `original-screenshot`：PDF/PPT/图片中的原图、曲线、表格、板书或排版本身承载了信息；保留经过查看的原始页/区域截图。
- `editable-diagram`：资料明确给出了流程、层级、结构、时序、比较、变量关系或数学/几何构造，且可编辑的简图比截图更适合复习；根据这些已读关系绘制 Excalidraw 图。

视觉决策使用两种信号：

1. **证据信号**：来源明确出现了坐标轴、曲线、点/线/面、角度、几何构造、向量、数轴、概率树、矩阵布局，或能定位到两个以上对象之间的空间/方向/变化关系。
2. **解释效用信号**：模型能用一句话说清“这张图要帮助学习者回答什么问题”，例如“看出斜率变化”“区分条件概率的事件范围”“沿概率树追踪路径”。

两类信号都要检查。只要能指出图会澄清的具体难点，且资料足以支撑图中内容，就在本轮配图，不必等用户点名 Excalidraw。只有关键词或概念名字、没有可画内容时不能硬画；简短定义已经清楚时可不画。解释效用决定“值得画”，不授权新增学科知识。缺少精确数值但定性关系明确时可画示意图，标注“示意图/未按比例”；连形状、方向或关系都不明时，保留缺口，不凭“示意图”绕过证据不足。

可使用的 `visualType` 包括：`coordinate-plane`（坐标系/点/区域）、`function-curve`（函数变化或曲线趋势）、`geometric-construction`（三角形、圆、角、辅助线等）、`number-line`（区间/不等式/数轴）、`vector-transform`（向量与变换）、`probability-tree`（概率树）、`matrix-layout`（矩阵或表格结构）和 `conceptual-schematic`（概念结构）。普通流程图仍使用 `conceptual-schematic`，不要为了覆盖类型而重复画图。

不要仅凭“图”“模型”等关键词画图，也不要仅因公式简单就跳过：例如已给出的函数用坐标图更容易看出变化时应画。原图清晰且已能解答理解问题时，优先 `original-screenshot`；需要编辑、简化、突出局部或补充不同视角时再重绘。原图与重绘图并存时标明两者区别。通常一张图回答一个问题；多个视角确实解释不同难点时可用多张，不要求每页配图或用同一内容凑图数。

### 数学与几何图怎么画

- 已给出的公式可以经过可复算的计算转成曲线或几何位置。例如依据 $y=x^2$ 采样作图，不属于凭常识补写知识；不能自行补上来源缺失的方程、概率、边长或结论。
- 区分数学坐标和画布像素。坐标系采用一致的变换，注意画布纵轴向下；涉及角度、圆、距离时两轴比例一致。曲线标清公式和范围；为展示而选的窗口标为“展示范围”，不能冒充定义域。
- 函数点从已给公式计算；遇到无定义点或间断处分段，不能跨断点连线。精确数值图优先用确定性采样生成原生折线；数据不足时只画来源支持的趋势。不把手绘近似当作测量或数值求解结果。
- 几何图保留已知的相交、平行、垂直、角度和长度约束；数轴保留开闭端点；向量保留起点和方向；概率树保留分支条件。用于帮助阅读的辅助线/坐标轴可以加入，但需与来源给定量区分，不新增证明结论。
- 坐标轴、刻度、曲线和点标注使用原生可编辑元素，可用分组一起移动。它们不是流程节点，不强制把轴端绑定到形状或把点名塞入容器；节点内部标签和节点间连接才使用双向绑定。
- 先计算，再布局，再检查图：标签是否遮挡、曲线是否越界、比例是否误导。图注只写必要的理解提示和“示意/展示范围”，不新增长篇课堂叙述。

## 画什么，不能画什么

绘图输入必须来自已读的 SourceMap/来源片段、已有有效笔记，或按 note-writing.md 取得并标注的外部补充数据：

- 节点只放资料中出现的概念、变量、步骤、实体或页面；
- 箭头只表达资料明确支持的顺序、包含、依赖、对比、输入/输出或应用关系；
- 关系方向不清、ASR 损坏、图中看不清的文字和缺失公式保留 `待确认`，不要用常识补箭头或补节点；
- 图形保持小而可读，优先一张图解释一个知识对象或一个关系簇；不要把整节课重绘成海报。

图形标题和图注使用知识表达，不写“课堂上老师画了……”。可写“条件概率的事件范围关系｜根据《资料名》PPT 第 8 页重绘”。

## 如何调用 Excalidraw

先在临时工作记忆中形成一个最小 `DiagramIR`，再交给 Excalidraw 适配器：

```text
DiagramIR = {
  goal, visualType, utilityQuestion, scaleNote,
  nodes?, edges?,
  geometry? {sourceFormula, domain?, displayWindow?, constraints?, computedPoints?},
  sourceRefs,
  uncertainties[]
}
```

`DiagramIR` 只表示本次图形的语义，不进入长期 Knowledge State，也不取代 LessonModel 或 Alignment。这样可以在没有 Excalidraw 的环境中继续生成文字，或以后替换 MCP、SDK、CLI 而不改变知识协议。

这一步必须真正执行能力探测：只要 `visualNeed=editable-diagram`，先调用原生 CLI 的 `help` 或 `status`；若宿主报告 CLI 不可用，再探测已接入的 MCP/App；两者都不存在时，生成并校验本地场景。不能只在提示词里写“可以画图”然后直接交付纯文字。只有视觉决策明确为 `none`，或来源没有可表达的结构关系，才跳过 Excalidraw。

### 强制审核门

在交付 Human Note 前，逐节检查以下信号：

- 是否存在两个以上概念、步骤或变量之间的方向关系；
- 是否存在“先后、输入/输出、依赖、包含、对比、分层、循环”中的任一种；
- 是否有 PDF/PPT/图片中的结构图、流程图、坐标图、关系图或板书布局；
- 是否有一段文字需要读者同时比较多个对象或沿路径理解机制。
- 是否出现坐标、函数、斜率、截距、向量、面积/区域、角度、三角形、圆、数轴、分布形状、概率树或矩阵等数学/几何信号；
- 模型是否能提出一个具体的图形学习问题，且答案依赖对象的位置、方向、路径、形状或变化，而不是只依赖文字定义。

命中信号后必须完成视觉判断：按“按理解问题选择表达”确定形式。理解问题依赖形状、位置、移动或并排对比，或转写显示老师在讲一张未提供的图时，选择 `editable-diagram`（原图可用时选 `original-screenshot`）并立即执行；只有没有空间含义的流程或对照，才由 Mermaid 或表格完成。若只是名字/关键词、没有额外理解收益、用户明确只要文字或证据不足，可选 `none`，在临时工作记忆中记一句具体理由，不写永久审核报告。对数学/几何图记录 `visualType`、`utilityQuestion` 和适用的 `scaleNote`；定性图注明“示意图/未按比例”。工具选择：坐标图、函数曲线、曲线移动、数轴、多面板对比和复习地图一律用 Skill 自带脚本生成本地场景（它们按公式计算点位，并自带版式检查）；带标签的小型示意图可以用原生 CLI/Automate 或已接入的 MCP/App 创建，也可以用 `excalidraw_figure.py` 的 `box`/`arrow`；编辑用户已有的场景时优先用原生 CLI。能力探测每次运行一次即可，不要每小节重复探测；确认应画后，不能因没有原图或没有 MCP 就默默跳过。

原生 CLI 作用于 Obsidian 中已注册的 Vault；本次写入目标不是该 Vault（例如在副本或测试目录中试运行）时，不对正式 Vault 调用 CLI，改用本地场景生成并如实报告。优先读取 [references/obsidian-excalidraw-cli.md](obsidian-excalidraw-cli.md)。原生 CLI/ExcalidrawAutomate 适合创建带标签的示意图和编辑已有场景：它会把简化的形状、标签和箭头请求序列化为真正的绑定元素，并保存现代 `.excalidraw.md`，但它的基本元素是方框、标签和箭头，不会替你计算曲线。没有 CLI 时，可以使用当前环境已经接入的 Excalidraw MCP/App（工具名称可能显示为 `excalidraw`、`create_diagram`、`create_from_mermaid` 或同类名称）：

1. 先把绘图目标、节点、关系、来源定位和不确定项整理成最小说明；不要把完整转写再次发送给绘图工具。
2. 要求返回可编辑的 Obsidian-native scene，优先是 `.excalidraw.md`；必要时再请求 PNG/SVG 预览。
3. 将工具返回的场景保存到 Human root 的 `_assets/learning/diagrams/`，用稳定主题名和内容哈希去重；预览图也放在同一目录。
4. 按“嵌入与排版”放在对应小节讲解文字之后，写成 `![[图形.excalidraw.md|宽度]]`。这个嵌入指向可编辑源文件，不是把 Excalidraw 当成一张独立 PNG。宿主不支持嵌入时才使用普通相对链接，并在图注中说明“可编辑图”。

对节点连接图，保存前确认：形状的 `boundElements` 反向列出其内部文字和连接箭头，内部文字的 `containerId` 指向形状，连接箭头的 `startBinding`/`endBinding` 指向真实节点且两端反向列出箭头。只在画面上相交不能冒充绑定。几何图中的独立标签、坐标轴和曲线不受此容器要求约束。运行 `scripts/validate_excalidraw.py` 检查实际使用的绑定一致性。

保存前运行 Skill 自带的 `scripts/validate_excalidraw.py` 做轻量确定性检查：支持 `.excalidraw` 与 `.excalidraw.md`，检查顶层类型、版本、元素数组、元素 ID 唯一性、基本几何字段、文字容器双向关系和箭头端点双向绑定。它不是完整 Excalidraw schema，也不验证数学正确性或排版；排版交给 `scripts/lint_excalidraw_layout.py`，渲染检查交给 `scripts/render_excalidraw_preview.py`。另需回算关键点/约束并亲眼看渲染结果；有 Obsidian 时确认 Reading View 嵌入，可通过 CLI `export` 检查预览。没有可用渲染器时如实报告仅完成文件检查，不能声称已通过渲染验证。

Excalidraw 官方 MCP App 是一个独立的 MCP 服务；它可以把自然语言或结构化绘图要求变成可编辑场景，默认是手绘风格，保存前把 `roughness` 改为 0 并跑一遍版式检查。若当前环境没有该 MCP/连接器，不要伪称已经调用：由 Codex 根据同一份受证据约束的绘图说明直接写出合法 `.excalidraw` JSON，或只保留原始截图并报告“未生成可编辑图”。不要为了接入 Excalidraw 在 Skill 中新增网络客户端、API Key、React 运行时或外部模型。

## 两层产物如何对应

- Human layer 保存 `.excalidraw` 文件及可选的 PNG/SVG 预览，并在正文中引用；附件属于 Human root，随笔记一起同步。
- AI layer 不保存 base64、整张图或重复 OCR；在已有 source `attachments` 结构中记录 `assetRef`、文件哈希、原始 page/slide/line locator、`kind`（`source-image` 或 `excalidraw`）和 `generatedFrom`（`source-derived`）。若现有 AI schema 没有 `kind`/`generatedFrom`，保留已有字段并把说明放在对应 card 的短 `uncertainty`/`sourceRefs` 中，不新建一套图形数据库。
- 图形引用必须能回到一个 Human Note 小节和至少一个来源定位。图形的存在不改变知识对象的 stable ID，也不代替文字中的定义、条件、公式和边界。

## 清理与失败

只保留最终被笔记引用的 `.excalidraw` 和预览图。未采用的临时渲染、工具原始响应和中间图随 run workspace 一并清理；不扫描或清理用户已有附件。若 Excalidraw 调用失败，继续交付可读文字和可靠的原始截图，并标记缺口，不因可选图形阻塞整份笔记。
