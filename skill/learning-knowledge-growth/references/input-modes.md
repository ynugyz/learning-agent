# 输入资料读取方式

本参考只在输入不是普通 TXT/Markdown 时读取。目标是获得可追溯的证据，不是先替用户写一篇摘要。

## 课堂转写

- 直接读取文本，保留原始文件不变。
- 记录文件名、范围和行号/段落范围。
- 去除口头重复时，保留重复中新增的例子、强调、限制、方法建议和教师观点。
- ASR 不清楚的术语、公式或数字保留原位置并标为不确定。

## PPT / PPTX

使用当前环境可用的演示文稿读取工具或 Presentations skill：

- 读取每张相关幻灯片的标题、正文、备注、表格、公式和图示；
- 记录 slide number，图表或流程图要保留其结构关系；
- 不能从图中确认的文字、箭头方向或公式标为缺失/待核对；
- 不把“标题列表”直接当成知识结构，结合正文、备注和相关转写判断含义。

## PDF / 教材 / 文档

使用 PDF 或 documents skill 的读取能力：

- 先确定页码范围和文档是否为扫描件；
- 页面布局影响公式、表格、脚注或图示时，先渲染相关页再理解；
- 记录页码、章节标题、表格位置和抽取方式；
- 只把实际读到的内容交给后续编译，缺失页或不可读区域不能由模型常识补齐。

## 图片 / 扫描资料

- 读取可见文字、板书、公式、表格和图示；
- 对模糊、遮挡、裁切和无法辨认的区域保留位置说明；
- 只有在内容清晰且能回到图像位置时才进入正式知识笔记。

## 项目文件 / ZIP

- 先查看目录、manifest、README 和入口文件；
- 只读取与用户指定主题有关的源文件、示例、配置说明和图表；
- 跳过依赖目录、构建产物、缓存和无关生成文件；
- 对代码保留语言、文件路径、函数/类名和关键调用关系，便于后续检索。

## 混合资料

每个文件单独记录类型和来源，再按用户任务范围对齐。课堂资料与配套教材同时提供时，默认围绕课堂主题，教材帮助确认必要术语和条件；不能把同章全部段落自动写入正文。用户明确要求整理整章或各材料并重时，按该范围覆盖。不同文件互相冲突时，简短保留差别及来源和适用范围；不能因为某个格式抽取更整齐就覆盖另一个来源。完整阅读与正文展开程度分开，具体见 `note-writing.md`。

## PDF / PPT 原图进入笔记

默认按学习价值选图，无需用户逐张指定，也不要求每页笔记都配图：

- **适合保留**：流程图、结构图、曲线与统计图、空间关系、必须结合排版才能理解的表格或推导。
- **通常转为文字**：纯文字幻灯片、普通定义和列表、可准确表达为 Markdown 的简单表格与公式。图中若包含无法确认的公式，保留清晰原图并标明缺口，不猜写。
- **不收录**：装饰、封面、重复图、与当前主题无关的截图。不要为凑版式而新增知识或生成一张看似原图的替代图。

### 选取与插入

1. 用当前可用的 PDF / 演示文稿工具将相关页或区域渲染到临时工作区。先确认原文件和原始位置：PDF 用从 1 开始的物理页序号（印刷页码另注），PPT 用原始幻灯片序号；选页导出后不能按新 PDF 的页序号冒充原 slide number。`.ppt` 如需转换，保留原件与页序映射。读取备注不等于渲染了可见幻灯片。
2. 查看实际渲染结果，再选原图或合适区域。裁切须保留标题、图例、坐标轴、单位、箭头和必要脚注；避免截断条件或改变图意。优先清晰的 PNG，照片可用 JPEG/WebP；不要放大模糊图片后声称恢复了细节。无法可靠渲染时，继续整理已读到的文字并说明配图缺口，不伪造图片，也不让可选配图阻塞整个笔记。
3. 在对应知识小节附近放图，前后保留必要的文字解释。情境引入可用短语，不需要复述授课过程；图注用简短说明加原始出处，例如 `状态转换图｜《资料名》PPT 第 8 页`。不同概念不靠截图直接拼接；图片不能替代已能读清的关键公式、条件和步骤。
4. 将最终选用的图片放在 Human root 的 `_assets/learning/`，用相对于笔记文件的 Markdown 图片链接；已有明确 Vault 根目录时也可用可解析的 Obsidian 图片嵌入。不要使用临时路径、本机绝对路径、`file://` 或远程临时 URL。保持笔记和附件的相对目录关系，换电脑后一起同步即可显示。
5. 按图片内容哈希复用同一附件，不按运行日期重复导出；重复执行相同输入应优先复用已验证、来源哈希与位置均匹配的图片，避免再次渲染。源文件变化则重新检查相关页，不能继续把旧截图当作当前来源。AI 层只保存来源位置、附件相对路径和哈希；不复制图片、base64 或整页 OCR。
6. 交付前检查图片实际存在且能显示、图注与原页一致、正文链接可解析。清理临时工作区前确认笔记引用的是最终附件；仅本轮生成且未采用的临时图片可随工作区删除，不扫描或清理整个 Vault 的旧附件。

### 可选附件工具

需要可靠保存图片和生成跨平台链接时，使用 Skill 自带的 `scripts/attach_source_image.py`（Python 3.10+，仅标准库）：

```text
python <skill目录>/scripts/attach_source_image.py --human-root <Human目录> --note <目录内笔记.md> --image <已查看的渲染图.png> --source <原资料.pdf> --page 12 --alt "模型结构图" --region "右侧结构图，含图例"
```

PPT/PPTX 使用 `--slide 8` 替换 `--page 12`。不裁切时可省略 `--region`。`--note` 支持 Human root 内的绝对路径或相对于它的路径。该工具只复制原图字节、按完整图片哈希去重并返回 JSON，不渲染、不重绘、不修改笔记，不验证页数上界或截图与原文的语义对应。

把返回的 `markdown` 插入目标小节；将 `assetPath`、`imageHash`、`source.hash` 和 `source.locator` 合并到既有 AI 来源条目的附件信息中（字段映射见 `ai-index-protocol.md`），不要把工具响应另存为永久清单。Python 不可用时，可用文件工具按同样的存放、去重和链接规则完成；不要为了可选工具改动用户的系统环境。
